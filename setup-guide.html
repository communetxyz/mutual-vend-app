01

Gather the essentials.

The machine

Your purchased KSJ unit, its correct power supply or charged battery, any keys or service-access tools, and one empty compartment. Inspect for transit damage before powering on.

Done when: it powers on normally.

A supported browser

Google Chrome on Android, macOS or Windows. Turn Bluetooth on. On a Mac, allow Chrome in System Settings → Privacy & Security → Bluetooth when prompted.

Done when: Chrome can show a device picker.

A way to compare

Keep the supplied APK and PDF on hand. For USB testing, bring a simple USB light or meter. Label the actual doors with removable numbers if the cabinet is unclear.

Done when: you can identify each physical door.

iPhone/iPad Safari and iOS Chrome are not a supported direct Web Bluetooth path for this app. Use an Android phone or laptop beside the machine. See Chrome’s platform and permission guidance. Windows requires compatible Bluetooth hardware; Linux is not the default field-test path.

02

Open or run the app.

Option A · Hosted HTTPS app

  1. Open Mutual Vend field app in Chrome.
  2. Let it load once while online. The production app caches its interface and this guide for later offline use. Install from Chrome’s menu if offered.
  3. Reload once, then briefly turn off internet and check that the app still opens. Bluetooth stays on.

Offline cache applies to the production build. Saved inventory belongs to this URL and browser; it will not automatically appear at localhost or on another phone.

Option B · Run on this Mac

The working checkout is already at /Users/wk/mutual-vend-work/mutual-vend-app. Double-click Start Mutual Vend.command in that folder, or run: 

cd /Users/wk/mutual-vend-work/mutual-vend-app/field
npm ci
npm run dev

Open http://localhost:5173 in Google Chrome. Keep Terminal running for the session. Node.js 22 is recommended.

Option C · Android over a USB cable

  1. Run the app on the computer using Option B.
  2. On Android, enable Developer options → USB debugging. Plug the phone into the computer with a data cable and accept its debugging authorization.
  3. With Android Platform Tools installed, run:
adb devices
adb reverse tcp:5173 tcp:5173

Then open http://localhost:5173 in Chrome on the phone. The phone’s Bluetooth talks directly to the machine. The computer only serves the app. Disable USB debugging afterward if you no longer need it.

A normal LAN address is not enough.http://192.168.…:5173 is an insecure origin and does not enable Web Bluetooth. Use the hosted HTTPS app, localhost on the laptop, or Android USB forwarding. Do not disable browser security to work around this.
Fresh clone, production build, and verification commands 
git clone --branch feat/ksj-field-app https://github.com/communetxyz/mutual-vend-app.git

The preview is at http://localhost:4173. For browser tests: npx playwright install chromium, then npm run test:e2e. Static files are in field/dist/. Always serve that directory; opening its index.html as a file is not the Bluetooth path.

03

Try a practice session.

  1. Select “Try a simulation.”Click Start practice session. You should see Handshake confirmed, 82% simulated battery, and twelve closed doors.
  2. Open door 1 once.Select door 01 on the cabinet. Check the confirmation, then click Open door 1 once. Its label changes to OPEN.
  3. Close the simulated doors.Use the button below the cabinet. Watch the readback return to CLOSED.
  4. Try the failure path.Expand Device tools, set Simulated failure to No replies, and click Refresh status. You should get an unknown-result timeout. Restore Normal replies and refresh again.
  5. Disconnect before switching to hardware.Click the unplug icon. Choose Real machine. Practice checkmarks and collection records remain labeled as practice.
Done when: you have seen both a successful simulated door cycle and a timeout without automatic retries.
04

Connect the real machine.

  1. Close the original app.Only one client may be able to hold the BLE connection. Keep other phones and Bluetooth diagnostic apps disconnected.
  2. Name your local machine record.Use the settings gear while disconnected. Set its name and location. Leave PDF command profile and F0=open for the first test. The Bluetooth name is saved after the first successful connection.
  3. Press Connect machine.Choose the machine in Chrome’s Bluetooth picker. Likely prefixes include KSJ, B000, or YJKJ. If it does not appear, cancel and tick Show all nearby devices, then try again. Select only the unit you own.
  4. Wait for the handshake.The app discovers the service, subscribes to notifications, sends the handshake, and waits for its positive reply. It then queries device information and all doors.
  5. Check the readback against reality.With all doors physically closed, the app should report closed. If the states are reversed, check one known open door before selecting the inverted sensor setting while disconnected. If states are unknown, inspect Activity before continuing.
  6. Arm this session.Tick I’m beside my machine. The app resets this checkbox at disconnect. Buttons stay disabled while another command is running.
Ready means a reply arrived.The app never treats connection or GATT write success alone as a completed handshake. If the firmware sends a different acknowledgment, the session stays unavailable and the raw reply appears in Activity for diagnosis.
Done when: the expected device is connected, handshake confirmed, and a closed door’s reported state agrees with the hardware.
05

Open the first door.

  1. Use an empty compartment.Stand next to the machine and identify physical door 1. Keep fingers out of the latch and hinge path.
  2. Tap door 01 and review.The confirmation identifies the machine, Bluetooth name, profile and outgoing command. Click Open door 1 once.
  3. Wait and observe.The app checks a fresh closed state first, writes one command and waits for that door’s OPEN report. Watch for the latch releasing and the correct compartment opening.
  4. Close it manually.There is no powered “close” command in the supplied protocol. Close the door and wait for CLOSED, or use Refresh status.
  5. Record the result.Check the first-door step in Field guide only after the physical behavior and readback agree. Export the session if anything is unclear.
If it times out, stop tapping.The door may still have moved. Inspect it, close it, refresh the readback, and decide whether another single attempt is appropriate. The app never automatically retries an unlock.
Done when: one command opens the intended compartment, the open sensor is reported, and manual closing returns a closed report.
06

Check all twelve doors.

Work through doors 2–9 individually. Note any numbering mismatch on the physical cabinet. Then check 10, 11 and 12: the supplied sources disagree on these three command bytes.

Profile Doors 1–9 Door 10 Door 11 Door 12
PDF (default) 01–09 0A 0B 0C
APK 01–09 10 11 12

Every value above is hexadecimal. APK 10 means decimal 16, not decimal 10.

  1. Test door 10 once with PDF.
  2. If it fails, inspect all doors before proceeding. Disconnect, change Door command profile to APK in settings, reconnect, verify closed states and arm again.
  3. Test doors 10–12 individually with the alternate profile. Do not cycle every door at once.
  4. Keep the profile that matches your board, and record it in the results below.
Done when: every displayed door number has a known physical match and each reports a verified open/close cycle.
07

Stock, collect, and keep records.

Record the compartment

Open Inventory → Edit stock. Add a product name, the actual count inside, reference price, category and any expiry/refill notes. Pausing a slot prevents collection from it.

Count physically before saving.

Collect one item

With the session armed and the door closed, click Collect. Confirm the unlock. After inspecting the open compartment, choose I took one item or No item taken.

A sensor report alone never reduces stock.

Keep the evidence

Activity records pending, opened, collected, cancelled or unknown outcomes. An uncertain operation can be inspected and resolved there later. Export the session and inventory backup.

Confirm collection only once.
This is an operator field app.Prices are reference labels. It does not charge a card, send a crypto transaction, authorize customers, or prove payment. Existing web3 pages are preserved separately in the repository; the payment-to-KSJ workflow is not integrated. Bluetooth commands are not a substitute for a secure paid-vending architecture.

Catalogs, machine settings and the collection ledger are stored in this browser. The app has no stock sensor or cloud sync. A practice collection never changes real inventory. A real collection reduces its recorded count only after your explicit confirmation. If a page closes mid-operation, the pending record is restored as unknown.

Backup and move to another device

  1. In Field guide, click Export inventory backup. Save the JSON file somewhere you can find it.
  2. On the other device, open the app, remain disconnected, and use Import backup.
  3. Review the number of machines before replacing the local records. Reconnect to obtain fresh hardware states; backups never establish a live connection.

QR labels

Machine settings accepts a pasted QR URL or a camera scan. The last URL path segment becomes a local label. Scanning never automatically opens a link. It does not rename, register, transfer ownership of, or bind the controller in the vendor’s cloud.

08

Check power and USB.

  1. Refresh status. Battery-powered units should report a percentage, including 0%. Non-battery mode is labeled External power.
  2. If the machine has a USB output, connect a harmless USB light or meter.
  3. Expand Device tools → USB on. Review and send the command. Check the light or meter.
  4. Send USB off and verify physically. The UI deliberately says command written, not power confirmed.
  5. Disconnect and reconnect once. Verify that a new handshake and fresh state queries succeed.
The USB documentation is incomplete.The APK has complete on/off packets; the PDF instead lists different one-byte values and an unframed timer. The implementation uses the APK packets and does not guess the timer protocol. Skip USB if your board lacks the port or the vendor confirms a different board variant.

On: 88 F0 01 88. Off: 88 F0 00 88. No positive USB-status acknowledgment was verified from the supplied material.

09

Troubleshoot calmly.

What you see What to do
No Web Bluetooth / insecure origin Use Chrome on Android/macOS/Windows, with HTTPS or localhost. For an Android local session use USB forwarding. iOS is not supported for this direct transport.
Machine absent from picker Power/wake it, move closer, close the original app, and try Show all nearby devices. Confirm OS Bluetooth permission for Chrome.
Expected-name mismatch Pick the stored device name. If its name actually changed, disconnect and update Expected Bluetooth name in settings after verifying the hardware.
No FFC0 / FFF0 service Wrong device or different board. Export the log and compare the service UUID with the vendor. Do not send arbitrary bytes to a guessed characteristic.
Handshake timeout / rejected Export Activity. Compare the received bytes with the supplied PDF photograph. Power-cycle only with the vendor’s normal instructions, then reconnect. The app will not unlock before a positive handshake.
States remain unknown The query may be unsupported or the reply malformed. Preserve the raw bytes. Controls remain unavailable until a closed state is known; use the vendor app to establish a baseline.
Open reports closed (or reverse) Check a known open door and a known closed door. Then disconnect, change sensor interpretation, reconnect and repeat the baseline check.
Only doors 10–12 fail Inspect first, then try the alternate PDF/APK command profile as described in step 06.
Unlock timed out / disconnected Outcome is unknown. Inspect the physical door, close it, and refresh. Never assume another attempt is needed merely because a reply was lost.
Bluetooth disconnects in background Keep Chrome and the screen active during the test. Reconnect, re-check closed states, and re-arm. Background vending is not supported.
Inventory looks empty on another device Storage is per browser and origin. Export/import your backup. Hosted HTTPS and localhost have separate data.
Storage error Export the original storage using the recovery button before resuming saves. Free browser storage or use a regular non-private window.
Use the original APK as a comparison tool

On Android, install only the supplied APK from your trusted seller. Android may require permission to install from the file manager. Open it and enter the account/password already provided in the chat; they are intentionally absent from this guide. Its login requires the vendor service. Grant Bluetooth/Nearby devices and any legacy location permission it requests. Disconnect it fully before reconnecting Mutual Vend.

No vendor login has been verified during development. The app’s static contents were inspected, not executed on a physical phone. If both apps fail, record the exact board name, power state and symptoms for the seller.

11

What is implemented?

Capability Implementation Evidence boundary
Scan/connect, handshake, disconnect Implemented Real BLE + separate simulator; positive handshake reply required.
All 12 door buttons and lock readback Implemented Two explicit encoding profiles. Physical mapping remains to be tested.
Battery / external power Implemented Valid framed replies only; 0% is preserved.
USB on/off Implemented APK packets; physical confirmation required. Timer omitted because framing is unspecified.
Raw device logs Improved Readable TX/RX, timestamps, errors, mode labeling and export.
Inventory, collection, backup, checklist Added Local operator records, explicit collection confirmation, no automatic stock-sensor claim.
Vendor account login Direct BLE replaces it Account credentials are not required or stored by this field app. Vendor login was not exercised.
QR label / camera Implemented locally No cloud binding or firmware rename. APK name input is read-only and rename helper is not wired to a live action.
Paid public vending Not integrated No customer payment, payment verification, refund handling or production access control. Older web3 code is separate.
Unattended operation / iPhone BLE Not supported here Requires another transport or a local hardware gateway, plus hardware testing.

The supplied APK is a service tool, not a complete customer storefront. This replacement covers its active local control paths and adds field operations. The vendor’s account service, arbitrary RSSI/MAC scanning and any undocumented provisioning remain outside the browser implementation.
